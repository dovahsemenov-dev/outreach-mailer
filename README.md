# Outreach Mailer — автоотправка откликов на IT-вакансии (QA) по email

Берёт вакансии из `vacancies.json`, для каждой генерирует персональное письмо
через LLM (DeepSeek и совместимые API) и отправляет пакетом через SMTP
Mail.ru с твоего адреса. Почтовый ящик **не читается** — только отправка.

## Состав проекта

| Файл | Что это |
|---|---|
| `main.py` | оркестратор: чтение вакансий → генерация → отправка → журнал |
| `llm_writer.py` | генерация темы и тела письма через LLM API |
| `mailer.py` | отправка через SMTP (единственное место, где читается пароль) |
| `config.py` | константы: хост, порт, модель, лимиты, пути. **Без секретов** |
| `profile.txt` | текст профиля кандидата — единственный источник фактов для писем |
| `profile_letters.txt` | компактный профиль, отобранный специально для писем |
| `find_hr_emails.py` | автопоиск HR-адресов на сайтах компаний из `sites_qa.csv` |
| `vacancies.json` | входной список вакансий (заполняешь ты) |
| `sent_log.csv` | журнал отправок (создаётся при первом запуске) |
| `drafts/` | копии сгенерированных писем до отправки (создаётся при запуске) |
| `.env.example` | шаблон переменных окружения |
| `settings.example.json` | шаблон настроек панели |
| `настройки_бота.bat` | открывает веб-панель управления (браузер) |
| `запуск_бота.bat` | запуск бота одним кликом |
| `panel.py` | сервер панели (только localhost) |
| `tests/` | тесты на моках, без реальной отправки |

Файлы с личными данными (`profile.txt`, `profile_letters.txt`, `resume.pdf`)
и секретами в репозиторий **не публикуются** — рядом лежат шаблоны `*.example`.

## 1. Установка

Нужен Python 3.10+. Из папки проекта:

```
pip install -r requirements.txt
```

## 2. Пароль приложения Mail.ru

1. Зайди на [mail.ru](https://mail.ru) под своим аккаунтом.
2. Настройки → «Пароль и безопасность».
3. Убедись, что включён доступ **по протоколу IMAP и SMTP** (раздел «Работа с
   почтой по протоколу IMAP и SMTP») — без этого SMTP-отправка из сторонних
   программ не работает.
4. Там же создай **«Пароль приложения»** для Почты. Скопируй его сразу —
   он показывается один раз.

Точные названия пунктов меню иногда меняются — ориентир: справка mail.ru,
запрос «пароли приложений».

## 3. Переменные окружения (два способа)

Все секреты живут только в окружении. В коде, конфиге и логах их нет.

**Способ А — файл `.env` (проще всего):**

1. Скопируй `.env.example` в `.env` рядом с `main.py`.
2. Заполни значения:

```
MAILRU_APP_PASSWORD=пароль_приложения_из_шага_2
DEEPSEEK_API_KEY=
LLM_PROVIDERS_JSON=llm_providers.json
```

Строка `DEEPSEEK_API_KEY=` нужна **только** если файла `llm_providers.json`
нет — см. раздел 4.
Файлы `.env` и `llm_providers.json` добавлены в `.gitignore` — в git они не попадут.

**Способ Б — переменные окружения Windows:**

PowerShell (только для текущего окна):
```powershell
$env:MAILRU_APP_PASSWORD = "пароль_приложения"
```

Навсегда (для всех новых программ):
```powershell
setx MAILRU_APP_PASSWORD "пароль_приложения"
```
После `setx` открой терминал заново — переменные появляются только в новых окнах.

В `config.py` впиши свой адрес отправителя (`SENDER_EMAIL`) — логин SMTP должен
совпадать с From, бот проверяет это при запуске.

## 4. Ключи LLM

Скопируй `llm_providers.example.json` → `llm_providers.json` и впиши свои
ключи. Схема поддерживает **несколько провайдеров** одной модели (в проекте
использовались бесплатные шлюзы DeepSeek — TokenHarbor, Goedel, ZRO, Orca —
22 провайдера). Файл в `.gitignore` — ключи не попадут в git.

Как работает ротация:

- провайдеры перебираются **по кругу** — нагрузка распределяется равномерно
  (у большинства лимит 6 запросов/мин);
- если провайдер упёрся в лимит (429), ключ не принят (401) или закрыт (402/403)
  — он пропускается, берётся следующий;
- сетевая или серверная (5xx) ошибка — один повтор этого же провайдера, потом
  следующий;
- ни один ключ не попадает в промпты и логи.

Вернуться на официальный API `api.deepseek.com`: удали `llm_providers.json`
и впиши ключ в `.env` строкой `DEEPSEEK_API_KEY=...` (модель `deepseek-flash`,
сверено с api-docs.deepseek.com).

## 5. vacancies.json

Список объектов. Поля:

| Поле | Обязательное | Что это |
|---|---|---|
| `title` | да | название вакансии |
| `company` | нет | название компании |
| `description` | нет | текст вакансии — чем полнее, тем точнее письмо. **Если пусто — холодный режим**: письмо-знакомство «продаёт» кандидата компании без ссылки на вакансию (для общих/кадровых адресов) |
| `hr_email` | да | адрес работодателя для отклика |

Пример (см. также `vacancies.example.json`):

```json
[
  {
    "title": "Тестировщик (manual QA)",
    "company": "Ромашка",
    "description": "Ручное тестирование веб-приложения, оформление баг-репортов, работа с Jira.",
    "hr_email": "hr@romashka.ru"
  }
]
```

- Вакансия без `hr_email` пропускается (запись в журнале со статусом `skipped`).
- Адреса, по которым уже есть запись `sent` в `sent_log.csv`, повторно
  **никогда** не отправляются.
- Лимит за один запуск настраивается в панели или в `settings.json`
  (`max_per_run`).

## 6. Запуск

```
python main.py
```

Что происходит:

1. Читаются вакансии, отсеиваются уже отправленные и дубли.
2. Для каждой генерируется письмо (LLM, русский язык, 80–150 слов,
   факты только из `profile_letters.txt` / `profile.txt`).
3. Каждое письмо ДО отправки сохраняется в `drafts/NN_компания.txt` —
   текст можно проверить глазами, даже если отправка сорвётся.
4. Пакет уходит через SMTP_SSL `smtp.mail.ru:465` — одно соединение на пакет,
   между письмами случайная пауза (настраивается в панели).
5. Каждое событие сразу пишется в `sent_log.csv` (открывается в Excel) и
   `logs/app.log`.

Время: пакет из 30 писем ≈ 10–30 минут — не закрывай окно до конца.

### Повседневное управление (шпаргалка)

**Панель управления (основной способ):** двойной клик по `настройки_бота.bat` —
в браузере откроется панель: лимиты, паузы, вложение резюме, редактор
компаний (добавить/удалить строку), пароли, статистика отправок. Жми «СОХРАНИТЬ
ВСЁ» — панель пишет `settings.json`, `vacancies.json` и `.env`. Окно сервера
держи открытым, пока работаешь с панелью. Настройки применяются при следующем
запуске бота.

**Запуск бота:** двойной клик по `запуск_бота.bat` — откроется окно, бот
отработает и покажет итог. Окно закроется по нажатию любой клавиши.

**Добавить компании:** открой `vacancies.json` в Блокноте, добавь записи
(формат — раздел 5), сохрани. Для писем «без вакансии» поле description оставь
пустым: `"description": ""`.

**Посмотреть результаты:** `sent_log.csv` открывается в Excel (кто, когда,
статус); тексты писем — в папке `drafts/`; подробности — `logs/app.log`.

**Остановить посреди запуска:** Ctrl+C в окне бота — уже отправленные письма
записаны в журнал, ничего не потеряется и не задвоится.

**Перезапуск безопасен:** адреса, по которым уже есть `sent` в журнале,
автоматически пропускаются — повторно письмо не уйдёт.

Ошибки:

| Что случилось | Что сделает бот |
|---|---|
| Нет `MAILRU_APP_PASSWORD` или ключей LLM | запуск не начинается, сообщение без значений |
| Неверный пароль приложения | весь запуск останавливается, понятное сообщение без пароля |
| Ошибка LLM | провайдер пропускается, берётся следующий (раздел 4) |
| Ошибка отправки одного письма | статус `error` в журнале, пакет продолжается |
| Разрыв соединения | переподключение, отправка продолжается |
| From не совпадает с логином SMTP | весь запуск останавливается (ошибка конфигурации) |

## 7. Тесты

```
pip install -r requirements-dev.txt
python -m pytest tests/ -v
```

Все тесты на моках — реальная отправка и обращение к API не выполняются.

## 8. Безопасность — коротко

- Пароль и ключи существуют **только** в `.env` и `llm_providers.json` (оба в `.gitignore`).
- `.env`, `llm_providers.json`, `settings.json`, `sent_log.csv`, `resume.pdf`,
  `profile*.txt`, `drafts/`, `logs/` и списки адресов добавлены в `.gitignore`.
- Пароль не попадает в промпты, логи, исключения и тесты (это проверяется тестами).
- Ключи LLM тоже не попадают в логи — логируется только id провайдера и код ошибки.
- Перед каждой отправкой проверяется: From письма совпадает с логином SMTP из `config.py`.
- Почтовый ящик не читается: никаких IMAP/POP3 и сторонних почтовых API в коде нет.

## 9. Конфиденциальность

Это портфолио-публикация рабочего проекта. Личные данные кандидата и
секреты в репозиторий **не включены**: профили, резюме, ключи API, пароль
Mail.ru, журналы отправок и списки адресов отсутствуют. Места в коде, где
подключаются личные данные, помечены маркером `[ЛИЧНЫЕ ДАННЫЕ]` и содержат
плейсхолдеры; шаблоны файлов приложены (`*.example`).
